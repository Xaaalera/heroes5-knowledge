# Команды xkit

В терминале Windows команды начинаются с `xkit`. Во [внутриигровой консоли](../modding/console.md) игровые команды вводятся без `xkit game`: например, `heroes` вместо `xkit game heroes`.

Пока первый терминал выполняет `xkit start`, для других команд открой второй. Справка доступна через `xkit --help`, `xkit game --help` и `xkit game army --help`. В игре используй `help` и `help army`.

## Разработка и выпуск

| Команда в терминале | Назначение |
|---|---|
| `xkit setup` | Выбрать установленную игру и рабочую папку проектов |
| `xkit new demo --resources` | Создать ресурсный мод |
| `xkit new demo-native` | Создать нативный C++-плагин |
| `xkit start demo` | Запустить тестовую игру и сеанс разработки |
| `xkit start demo --map WorkshopPolygon` | Запустить сеанс с указанной тестовой картой |
| `xkit build demo` | Собрать проект; для ресурсного мода получить H5U |
| `xkit release demo` | Выпустить пакет для игрока; ресурсный ZIP сохраняет отдельный H5U |
| `xkit diagnostics` | Прочитать диагностику текущего сеанса |
| `xkit doctor` | Проверить окружение разработки |
| `xkit language ru` / `xkit language en` | Выбрать язык сообщений |
| `xkit check --console` | Проверить семь сценариев консоли в тестовой игре |
| `xkit check --player` | Проверить пользовательскую поставку в тестовой игре |

У `build`, `release` и `start` имя проекта можно опустить, если проект уже выбран. После `start` сеанс продолжает работать; Ctrl+C останавливает его и закрывает собственную тестовую игру. Пошаговая установка и первый проект — в [руководстве SDK](../modding/devkit.md).

Перед `xkit check` останови текущий сеанс сочетанием Ctrl+C и закрой другие окна игры и редактора: проверка запускает собственную тестовую игру. Варианты `--console` и `--player` выполняются отдельно.

## Игровые команды

Команды этой таблицы вводятся в консоли игры. Для терминала добавь `xkit game` перед каждой строкой. `HERO`, `CREATURE`, `NAME` и другие слова в верхнем регистре — места для твоих значений, а не текст для копирования.

| Синтаксис | Действие и условия |
|---|---|
| `status` | Проверить связь с текущей тестовой игрой; не определяет готовность карты |
| `heroes` | Получить имена героев загруженной карты приключений |
| `army HERO CREATURE` | Прочитать количество существ выбранного типа у героя |
| `army HERO CREATURE --count N` | Установить итоговое количество: от 0 до 1 000 000 |
| `level HERO TARGET` | Поднять героя до уровня 1–40; уровень не понижает |
| `resource PLAYER KIND` | Прочитать ресурс участвующего игрока: номер игрока 1–8 |
| `resource PLAYER KIND --amount N` | Установить итоговый запас: от 0 до 100 000 000 |
| `teleport HERO X Y [--floor N]` | Переместить героя к координатам на карте; этаж по умолчанию 0 |
| `interact HERO TARGET` | Отправить героя к объекту с указанным игровым именем |
| `map NAME` | Запросить загрузку карты из папки Maps тестовой игры |
| `restart NAME` | Заново загрузить явно указанную карту |
| `menu` | Запросить возврат в главное меню |
| `screenshot` | Сохранить свежий кадр и вывести путь к PNG |
| `trace [--level LEVEL] [--after N] [--limit N]` | Прочитать сообщения общей диагностической шины |

Подсказки Tab помогают выбрать героя, карту и обозначение существа, например `CREATURE_ARCHER`. Имя героя бери из ответа `heroes`; имя объекта — из данных своей тестовой карты. Если имя содержит пробелы, заключи его в кавычки.

Для армии `--count 100` задаёт **общее количество 100**, а не добавляет ещё 100. Семь занятых слотов могут помешать добавлению нового типа. Команда уровня автоматически проходит доступные окна повышения; её текущий интерфейс не предоставляет выбора навыка.

## Примеры для героя

Если в ответе `heroes` есть `Brem`, можно выполнить:

```text
army Brem CREATURE_ARCHER
army Brem CREATURE_ARCHER --count 100
level Brem 20
```

Первая команда читает армию, следующие две изменяют тестовую игру. Пример терминала: `xkit game level Brem 20`. Команда `hero-level` не зарегистрирована; команда `army` не принимает количество третьим позиционным аргументом.

## Номера ресурсов

| KIND | Ресурс |
|---|---|
| 0 | Дерево |
| 1 | Руда |
| 2 | Ртуть |
| 3 | Кристаллы |
| 4 | Сера |
| 5 | Самоцветы |
| 6 | Золото |

Например, `resource 1 6 --amount 5000` устанавливает игроку 1 запас золота 5000. Значения сверены со скриптами поставляемой игры. В справке preview.5 подписи кристаллов и серы перепутаны; здесь указан правильный порядок, исправление подписи подготовлено в исходниках SDK.

## Загрузка карты и журнал

`restart` требует имя карты: `restart WorkshopPolygon`. Команда не угадывает текущую карту. После `map` или `restart` дождись её появления в окне игры, затем проверь `heroes`. Ответ об отправке команды и `status` подтверждают соединение; изменения армии или уровня отправляй после появления карты и доступности героев.

У `trace` по умолчанию уровень `info`, начало журнала `--after 0` и предел 16 записей. Допустимые уровни: `debug`, `info`, `warning`, `error`; предел — 1–64. `--after` позволяет продолжить чтение с позиции предыдущего ответа. Дополнительный `--console` просит вывести данные ещё и в штатную игровую консоль; видимость такого вывода отдельно не подтверждена.

Локальная команда `clear` очищает вывод внутренней консоли xkit. Она не стирает файл журнала. Параметр `--json` выводит структурированный результат в терминале, например `xkit game heroes --json`. Внутриигровая консоль сохраняет человекочитаемый ответ.

### Установить карту из примера

WorkshopPolygon не создаётся обычной подготовкой нового проекта. Сначала запусти и останови любой тестовый сеанс, чтобы появилась тестовая копия. Скачай [WorkshopPolygon.h5m](../assets/WorkshopPolygon.h5m) и скопируй файл без распаковки в `.local/test-game/Maps` выбранной рабочей папки xkit. Если карта уже есть, сохрани её прежнюю копию. Затем можно использовать `xkit start demo --map WorkshopPolygon` или `map WorkshopPolygon` в открытом сеансе. Устройство карты и ограничения её выпуска описаны в [статье о полигоне](../modding/test-maps.md).

## Обслуживание SDK

Это команды автора инструментов и рабочей папки; игроку готового мода они не нужны.

| Группа | Что делает |
|---|---|
| `xkit storage status` | Показывает состояние хранилища тестовых файлов |
| `xkit storage clean` | Очищает принадлежащие SDK устаревшие данные по его правилам |
| `xkit storage restore --help` | Объясняет восстановление сохранённого состояния |
| `xkit storage restore-dump --help` | Объясняет распаковку сохранённого дампа |
| `xkit sdk build` | Собирает готовые служебные файлы из исходников SDK |
| `xkit sdk release` | Собирает полный архив SDK для авторов модов |
| `xkit sdk recover-bank --help` | Объясняет восстановление прерванного тестового сеанса справочника |

Перед изменяющей файлы командой прочитай её `--help`; подтверждение успешного запроса не заменяет проверку результата. Если действие могло выполниться, сначала проверь состояние, а затем решай, повторять ли запрос.
