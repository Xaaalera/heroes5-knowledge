# Расстановка: технические правила и исправленные предположения

Технический справочник по **разделению отрядов, сортировке и выбору клеток**. Для начала со схемами смотри [разбор для игроков](../players/army-placement.md). Все адреса ниже относятся к [закреплённому EXE](universe-build.md); способ проверки указан в конце.

## Два уровня подготовки армии

`0x855240` готовит боевые записи до выбора клеток. При двух и более непустых исходных записях изученная ветка копирует типы/количества. При одной записи действует разделение. Это не исключает изменений исходной армии до вызова.

Для обычных CombatSize 1/2 предел M=4. Раннее предположение, что поле+0xdc обозначает тир и крупным автоматически положено M=2, было исправлено: это CombatSize, загрузчик ограничивает его 1…2.

| Отношение оценок R | Начальное K при M=4 |
|---|---:|
| R<0.5 | 4 |
| 0.5≤R<1 | 3 |
| R≥1 | 2 |

Затем RNG(1,100): результат≤30 уменьшает K; результат≥70 увеличивает K, если K<M. Далее `K=max(1,min(K,N))`. Это условия сравнения, не проверенные процентные вероятности генератора.

При K>2 и наличии Upgrades другая случайная проверка строго<50 может заменить тип внутренних стеков; крайние сохраняют исходный. Распределение количества: `q=N div K`, `r=N mod K`; первые r получают q+1, остальные q. Например 10 и3 дают 4/3/3.

Отношение R не равно оценке сортировки ниже. Для разобранного CHero числитель использует его армейный вектор/контекст, знаменатель — вектор противника без героя. Дополнительный контекст трактуется getter-функциями как тип недели. Например WEEK_OF_TOUGHNESS изменяет используемое здоровье на `H + H div 5`. Это статическая цепочка, не проверка всех недель Universe и всех реализаций интерфейса.

## Выбор алгоритма

`0x85a190` использует флаг `combat_active_auto_placement` и условие числа непустых исходных дескрипторов. Для обычного CAdvMapMonster прослежена связь с армией объекта карты; это не число уникальных портретов. `0x85a040` отдельно сохраняет ранее размещённые позиции и достраивает оставшиеся.

Расширенный путь: `0x859eb0 → 0x859cd0 → 0x8598e0`. В последнем защитный проход `0x8593c0` условный, общий `0x859670` выполняется всегда; затем — остаточные проходы по колонкам. Простой путь `0x85a110` имеет собственный fallback.

## Оценка отряда и равенство ключей

В цепочке `0x858d40` опора — синтетический CREATURE_PEASANT количеством 1, без героя; это не армия игрока. `0xbfaa70` строит агрегат:

```text
D = truncate(((minDamage + maxDamage) * N) / 2)
H = healthPerCreature * N
```

Умножение предшествует делению: для урона 1–2 и N=3 получается 4, а не3. Атака взвешивается целым суммарным уроном, защита — здоровьем. Оценщик читает защитный параметр опоры из+0x24, который эта цепочка оставляет нулевым, а не из поля обычной защиты+0x1c. Результат оценки и дробные параметры опоры усекаются к нулю.

В контроле коэффициенты DamageIncrease/Decrease были 0.05. Соседние caps 3/0.1 существуют в ресурсе, но функция оценки `0xa58d30` их не читает: нельзя добавлять эти ограничения по имени соседнего поля. Это не утверждение о формуле нанесённого боевого урона.

Обычная сортировка `0x85a700` сливает дорожки с убывающим шагом; равенство выбирает правую дорожку. Для 10 одинаковых рядов порядок 8,4,6,10,2,7,3,5,9,1. Сравнение 3280 последовательностей оценок длиной 0…7 над{0,1,2} с исходными инструкциями подтвердило обычную числовую сортировку; getter-зависимый компаратор этим перебором не проверялся.

В специальном компараторе `0x85aba0`: сначала нелетающие перед летающими; затем скорость, если `max(speed1,speed2) >= distance`; затем score. Для общего прохода `distance = width − deploymentColumns − 6`. [Исполняемый частный разбор](../assets/placement/placement_walkthrough.py) воспроизводит подтверждённый пример, не все ветки.

## Ряды, разрежение и глубина

Длина подхода измеряется `0x857b60`; окно стрелков `0x857e60` берёт первую минимальную сумму. Для spread (`0x858700`) шаг — **целая** часть `(R−1)/(N−1)`, затем прибавляется 0.001. Для первых N−1 индексов берётся усечённое i×step, последний — R−1. При R=10,N=3 набор{0,4,9}, не{0,5,9}. Сохраняется предыдущий порядок выбранных рядов; дополнительно проверяется занятость, с возвратом к предыдущему списку, если фильтр опустел.

Крупная фигура резервирует весь 2×2. `0xb3efb0` строит маску допустимых якорей из копии, не распространяет новые блокировки повторно.

[![Проверка крупного квадрата на полной сетке с обеими армиями](../assets/placement/pack_8-footprint.svg)](../assets/placement/pack_8-footprint.svg)

`0x85a2a0` вычисляет глубину размещения внутри поля. В наблюдавшемся Universe порог свободных больших позиций заменён с2L на3L; при L≥4 добавляется колонка. Минимум 2/3 связан с эффективным преимуществом «Тактики». Равные возможности сторон сбрасывают оба флага; дополнительный блокирующий предикат пока нельзя безоговорочно назвать конкретной специализацией.

## Связанные группы и запасные попытки

Гоблины и использующие их существа имеют отдельный выбор соседства (`0x858fb0`), а не только общую сортировку рядов. В выборе клетки учитывается вхождение в несколько списков; алгоритм жадный, не глобальная оптимизация.

У функции поддержки стрелков `0x8580e0` найдено использование мировых координат в локальной проверке. Для мирового якоря(13,5) фильтр пустой локальной зоны 3×10 не дал кандидатов, для(2,5) дал соседей. Поэтому «поддержка обязательно рядом со стрелком» не установлено.

У предполагаемого объединения одинаковых типов `0x8599d0` внутренний цикл оказался недостижим для корректного размера вектора. Проверены N=0,1,2,3,7,64. Сдвиг окна/повторные проходы существуют, но название ветки не доказывает работающее объединение. Исключение записи из попытки не равно доказанному удалению существ из армии карты.

Дополнительная оценка способностей `0xbfa360` имеет собственные условия/проверку целей. Для исследованного вызова вклад `min(uses,10) * value div 10`; исключены EXPLOSION 162 и DEATH_WAIL316. Полный смысл начального значения и всех предикатов пока не установлен; это не готовая формула дальнего урона.

## Уровень подтверждения

Арифметика сортировки, усечения, маски 2×2 и части split/spread проверялась исполнением исходных участков в эмуляторе. Изменения ширины Universe наблюдались в памяти отдельного запуска. Живой журнал элементалей подтверждает 7 попыток/4 позиции только своего обычного прохода. Остальные специальные режимы не получают его статус автоматически.
