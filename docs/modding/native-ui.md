# Нативные окна: почему Visible=true недостаточно

У ArmyWnd уже стоял Visible=true, но это не делало справочную армию хранилища видимой. Шаблон описывает компоновку; игра ещё должна выбрать окно, передать модель и заполнить дочерние элементы.

## Что найдено в ресурсах

`data.pak/UI/Tooltips/CommonAdvObjTooltip/` содержит ArmyWnd размером 197×110, ArmyText и семь CreatureFace.1–7. У ячейки рамка 40×40, CreatureIconPlace 34×34 и CreaturesNumber. MonsterTooltip и CommonAdvObjTooltip уже ссылаются на этот контейнер.

Renderer ищет дочерние имена, а не узнаёт назначение окна по картинке. В исследованной входной модели виртуальные слоты+0x38/+0x3c/+0x40 относятся к условию наполнения, числу элементов и доступу к элементу. У просмотренной реализации шаг записи 24 байта; запись содержит ссылку текстуры и числовую/строковую подписи. Это описание изученной реализации, не универсальный C++ ABI.

## Почему отдельный корень оказался важен

1. Переключение общего renderer нашло панели, но не обеспечило подходящего заполнения и места для всех банков.
2. Рабочий прототип регистрировал отдельный корень окна в typedWindows копии Universe UIGameRoot.
3. Корень выбирался до штатного наполнения/компоновки по публичному названию объекта. Общие подсказки оставались на исходном пути.
4. Таблица прототипа содержит 19 названий для 12 семейств. Выбор по имени чувствителен к переименованию и совпадению названий; подтверждённого универсального Type-диспетчера из этого не следует.

Отдельное окно тайника бесов было видно в игре. Новые строки и все остальные семейства не получили такого же полного живого подтверждения.

## Две разные карточки армии

- ArmyWnd подсказки объекта — список портретов/подписей.
- SCreatureInfoTooltip боевого экрана — подробная карточка одного типа.

Для проекции создан справочный descriptor одного существа без героя и реального боевого стека; штатный CScreenTooltipController управляет карточкой и ПКМ. При смене грейда обновляются обе удерживаемые ссылки: только заменить картинку недостаточно. Подробное окно использует собственный CSimpleCreaturesRotator; единица в нём — синтетическая справочная численность, не разведанные враги.

## Жизненный цикл — часть механизма

У окна и проекций есть владелец и поколение. После Start/уничтожения экрана их ссылки освобождаются. В раннем опыте после очистки маски оставались размеры при нулевых указателях — это приводило к падению второго боя. Исправление сбрасывает все 24 байта структуры маски. Проверка только первого открытия такую ошибку не ловит.

Не считать готовым API найденную строку функции или vtable. Указатель окна, соглашение вызова, владение ссылкой, активный экран и поток выполнения проверяются отдельно.

## Контрольные точки изученной сборки

| Назначение | Адрес |
|---|---|
| Renderer списка армии | `0x5f8050` |
| Выбор корня до компоновки | `0x5f8800` |
| Источник tooltip боевого экрана | `0x546f40` |
| Создание creature descriptor | `0x4bd550` |
| Создание rotator | `0x789010` |

**Основание:** ресурсы, счётчик вызовов, отдельное окно банка и последующие native-проверки карточек 21–23 сентября. Адреса — только [закреплённая сборка](../reference/universe-build.md), не готовый SDK. Исходные игровые DLL не заменялись универсальным загрузчиком.
