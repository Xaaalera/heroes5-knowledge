# Начать разработку с xkit

xkit — наш набор инструментов для разработки модов Heroes V Universe. Он готовит тестовую игру, собирает мод и помогает проверить результат. Для игры с готовым модом xkit, Python и компилятор не нужны — начни с [каталога модов](../players/mods.md). Эта инструкция предназначена для автора мода.

## Что понадобится

- Windows 10/11 и установленная Heroes V: Повелители Орды с Universe.
- Python 3.10+ x64 и [uv](https://docs.astral.sh/uv/getting-started/installation/) для установки команды.
- Рабочая папка вне установленной игры — для проектов, тестовой копии и журналов.
- Для C++-плагинов — Visual Studio Build Tools с инструментами C++ и CMake. Установи компонент C++ CMake tools for Windows либо доступный в PATH CMake. Ресурсному примеру ниже компилятор не нужен: готовые файлы входят в SDK.

Нативные функции проверены на [зафиксированной сборке Universe](../reference/universe-build.md). Перед первой подготовкой закрой игру и редактор.

## Установить команду

1. Скачай `xkit-sdk.zip` из [preview.5](https://github.com/Xaaalera/heroes5-mod-devkit/releases/tag/v0.1.1-preview.5).
2. Распакуй его в постоянную папку. Открой терминал внутри распакованной папки xkit.
3. Выполни:

```text
uv tool install --editable .
uv tool update-shell
```

4. Открой новый терминал и проверь `xkit --help`. Должен появиться список команд.

`--editable` обязателен для этого способа установки: команда использует распакованные исходники и соседнюю папку runtime с готовыми файлами. Сохрани папку SDK. Если команда не найдена, сначала открой новый терминал; `xkit doctor` проверяет окружение.

## Выбрать игру и рабочую папку

```text
xkit setup
```

Укажи установленную игру и отдельную рабочую папку. Каталог игры содержит bin и data, исполняемый файл находится в bin. xkit сохраняет выбор — повторять его в каждом терминале не нужно. Разработка идёт в тестовой копии; установка служит источником файлов.

## Первый проект: метка в меню

```text
xkit new demo --resources
```

В рабочей папке появится mods/demo. Файл mod.json задаёт рецепт мода, files предназначена для дополнительных ресурсов. Созданный пример добавляет `[xkit: demo]` в подпись версии главного меню.

Запусти тестовую игру:

```text
xkit start demo
```

На первом запуске xkit подготовит тестовую копию и установит мод. Дождись сообщения о готовности и проверь метку в меню: это видимый результат H5U. Исходный игровой архив не редактируется.

Этот терминал остаётся занят сеансом. Для [команд игре](../reference/xkit-commands.md) открой второй терминал или используй [консоль в игре](console.md). Чтобы завершить сеанс, нажми Ctrl+C в первом терминале и дождись закрытия тестовой игры.

## Выпустить мод

После остановки сеанса:

```text
xkit build demo
xkit release demo
```

`build` создаёт отдельный H5U. `release` сохраняет его и создаёт ZIP для игрока: H5U, общая графическая DLL, лицензии и двуязычный README.txt. Команда показывает путь к результату; соседний build.json — отчёт разработчика, игре он не нужен.

<span id="dll-autoload"></span>

Игрок следует README.txt пакета: при первой установке сохраняет исходную графическую DLL игры, затем копирует bin и UserMODs из архива. Мод подключается при обычном запуске Heroes/Lobby. Общие DLL сохраняют, пока они нужны другим модам. Отдельный H5U подходит для уже подключённой совместимой графической цепочки.

## Разрабатывать C++-плагин

Перед изменением интеграции прочитай [обязательный архитектурный контракт](native-projects.md#architecture-contract): логика и интерфейс остаются в моде, адаптер связывает их с runtime, а инструменты разработки не требуются игроку.

```text
xkit new demo-native
xkit start demo-native
```

Открой `plugins/demo-native/plugin.cpp` в рабочей папке. В созданном примере найди `DisplayValue = 42`, замени 42 на 77 и сохрани файл. xkit соберёт промежуточную DLL и применит правку в той же игре. Дождись сообщения «Плагин обновлён». В журнале `.local/xalkit/logs/events.jsonl` новая запись `applied` должна содержать `observation.result` со значением 77; при ошибке сборки успешной записи не будет. Это проверяет результат функции примера, не изменение правил игры.

Такой режим называется горячей перезагрузкой, или HMR. C++ всё равно компилируется; вручную переносить промежуточные DLL не нужно.

Проверены добавление функций и экспорта ядра, сохранение состояния, отключение старых обработчиков и откат при отказе. Начальные загрузчики и графическая DLL обновляются при следующем запуске; новый функционал размещай в ядре или отдельном плагине. Перенос папки старого предиктора или справочника сам по себе не переводит его на HMR.

Останови сеанс сочетанием Ctrl+C. `xkit release demo-native` создаст отдельный DLL-пакет из исходников проекта. Каждый мод поставляется независимо с необходимыми общими файлами.

## Проверить результат и найти ошибку

| Симптом | Следующий шаг |
|---|---|
| xkit не найден | Открыть новый терминал после обновления окружения; проверить `xkit --help` |
| Нет готовых файлов или перевода | Проверить полный архив и установку с `--editable` |
| C++ не собирается | Проверить Build Tools и сообщения компилятора; отказ не означает применение правки |
| Игра не дошла до готовности | Прочитать сообщение запуска и `xkit diagnostics` во втором терминале |
| Новое поведение не появилось | Проверить сообщения сборки и применения, затем видимый результат |

Не повторяй действие вслепую, если оно могло уже выполниться. Проверь состояние и журнал. Параметры — в [справочнике команд](../reference/xkit-commands.md), работа внутри игры — в [статье о консоли](console.md).
