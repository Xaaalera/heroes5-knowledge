# Первый эксперимент

Начни с одного изменения, результат которого можно увидеть за короткий запуск. Например, с собственного текста в интерфейсе или одного параметра ресурса.

## Выбери уровень изменения

| Уровень | Для чего нужен | Основная проверка |
|---|---|---|
| Ресурсы и XDB | Описания, определения объектов, интерфейс | Загружен ли именно изменённый ресурс |
| Lua | Сценарии и логика доступного игрового API | Есть ли нужная функция в выбранном контексте |
| Нативный код | Изменения поведения исполняемого кода | Совпадают ли сборка, ABI и найденный механизм |

Начинай с ресурса или скрипта, когда ими можно решить задачу. Нативные изменения требуют отдельного исследования исполняемого файла.

## Найди источник

Определи путь ресурса и архив, из которого он взят. Для текста сохрани исходную кодировку. Для XDB проследи ссылки `href`: нужное значение может находиться в другом определении.

Правка распакованной копии ещё не означает, что игра использовала её. Проверка загрузки — отдельный шаг.

## Запиши эксперимент

Короткая запись может выглядеть так:

```text
Задача: проверить загрузку собственного текста
Изменение: один ресурс
Ожидание: текст появляется в выбранном окне
Проверка: открыть это окно в тестовой игре
Откат: убрать пакет и повторить проверку
```

Это пример плана, а не отчёт о выполненной проверке.

## Закрепи результат

Сохрани путь, версию, действие и фактический результат. Подробный порядок — в статье [«Как проверить изменение»](verification.md).
